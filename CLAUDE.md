# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, dependency-free technical binder site for FRC team 6996 Koalafied. No build step, no package manager, no tests, no linter. Deployed via GitHub Pages from `main` / root (custom domain in `CNAME`). `README.md` is the authoritative content-editing guide for the team; read it before changing the content schema. `GETTING-STARTED.md` is the team-facing run/edit/publish guide — keep its port, file map and rename counts true if you change any of them.

## Running locally

The site works by opening `index.html` directly (`file://`), which is a hard requirement — see below. For previewing, `.claude/launch.json` defines a `binder` config (`python3 -m http.server 6996`); use `preview_start` with name `binder`. The print version is at `/print.html`.

`scripts/remove-bg.py input.png [output.webp]` strips flat white backgrounds from CAD screenshots (needs Pillow + numpy).

`scripts/split-logo.py` regenerates `assets/img/logo-gear.svg` and `logo-core.svg` from `logo.svg` — the two layers the nav mark stacks so `wireGear` can spin the sprocket ring against a static koala. It picks the gear out by path index (the artwork is drawn back to front), guarded by a fill-signature assertion, so a re-exported `logo.svg` fails loudly instead of splitting in the wrong place. Both layers are written with one square viewBox centred on the ring's axis (560, 555.5 in source units) — that is what lets CSS spin it about `50% 50%` without wobble, and it means the two files must always be regenerated together. Gear renders *under* core: the banners sit on top of the ring in the artwork. The source ring is a C — the artwork never drew the two ~51° arcs the banners cover — which reads fine at rest but swings into view once it turns, so the script closes it: the teeth repeat every 45°, so a second `<use>` of the ring rotated 90° (empirically the best-aligning angle that covers both gaps, 2.8px mean radial mismatch) is clipped to two wedges over the gaps. Clipping rather than overlaying a whole second ring is what keeps the tooth shadows from doubling. `GAPS`/`PHI` are measured off a render, so re-deriving `GEAR` means re-measuring them too; the check is that the ring covers 360° of angle and that the at-rest stack still matches the unpatched one (it changes ~0.07% of pixels, all hairline antialiasing under the banners).

`scripts/make-og.sh` regenerates `assets/img/og-cover.png` (the link-preview card) by screenshotting `scripts/og-card.html` in headless Chrome at 1200×630. That card reads `content.js`, so it follows the robot name, tagline, accent and hero render automatically — re-run the script and commit the PNG after changing any of them. Keep the output PNG/JPEG, never WebP: some link previewers won't load WebP.

## Architecture

- **`content.js`** holds all content as `window.BINDER_CONTENT = {...}`: `team`, `hero` (image + callouts), `categories`, `sponsors`, `sections`. It's a script, not a `.json` fetched at runtime, so the site works without a server. Never switch to `fetch()`/ES modules for this reason.
- **Two independent renderers read the same content object:**
  - `assets/js/binder.js` → `index.html` (interactive web page)
  - `assets/js/print.js` → `print.html` (A4 sheets, uses `binder.css` + `print.css`)
  
  Both are plain ES5 IIFEs that build HTML strings. Shared helpers live in `assets/js/common.js` as `window.Binder` (`esc()` escapes, then `fmt()` allows `**bold**` and `` `code` ``; plus `pad`, `featureList`, `mixedTags`, `numbered`, `contentOk`), loaded between `content.js` and each renderer. The HTML files are near-empty shells.
- **Media block types** are dispatched by `b.type` in `mediaBlock()` (binder.js) and `flatten()` (print.js): `highlight`, `carousel`, `iterations`, `compare` (all in README), plus `video` (web only). Adding or changing a block type means updating **both** renderers — print.js flattens every interactive block into static figures.
- **binder.js flow:** `boot()` numbers sections by array order → `renderNav` / `renderHero` / `renderSection` → `wire*` functions attach behavior (`wireCompare`, `wireHighlights`, `wireIterations`, `wireCarousels`, `wireLightbox`, `wireScrollSpy`, `wireNavScroll`). Interactive blocks register their config in the `BLOCKS` map keyed by a data attribute so wiring code can look them up.
- **Header** carries the mark, a two-line lockup (number + name, season under it — `.wordmark-text`, stacked so all three read without the divider the single-line version needed), the category links plus Onshape, and the team-site / print / contents buttons. The same links are *also* in the overlay's `.menu-extra` row, which is what covers them below 940px where `.nav-links` hides. It rides transparent over the page and `wireNavScroll` adds `is-stuck` past 8px to fade in the background and hairline; the blur is withheld until then because a `backdrop-filter` over the top of the page blurs the hero's top edge. That class is **not** gated on reduced motion — it is a state change, not an animation — whereas the gear rotation in the same handler is.
- **Nav sizing** comes from two tokens, `--mark` (the logo) and `--nav-h` (the bar), with a `max-width: 600px` block stepping both down. `--nav-h` also feeds `scroll-padding-top`, the sticky offsets and the overlay's top padding, so change it there rather than hardcoding a height. `.nav-links` carries the auto margin that pushes the right-hand side over, so the ≤940px block that hides it hands that margin to `.nav-tools`.
- **The nav indicator** is a filled pill that slides between category links, driven by all four `--indicator-*` vars `moveIndicator` writes (x/y/w/h), not just x/width as the old underline was.
- **Contents overlay** (`.menu-panel`, built in `renderNav`): a full-screen sheet that deliberately sits *under* the nav (z-index 99 vs 100) so the menu button stays put and doubles as the close button via `aria-expanded` swapping two icons. The panel itself does not scroll — `.menu-scroll` does — which is what keeps the oversized `.menu-deco` gear parked against the viewport. Open/close follows the lightbox pattern (`hidden` → rAF → `is-open`, `transitionend` back, `documentElement.overflow` for the scroll lock); the `transitionend` handler filters on `e.target === panel` because the staggered rows bubble their own. Rows stagger off an inline `--i`; any `transition` declared on `.menu-panel a` outweighs the shared `.menu-sheet > *` rule and silently drops the links out of that stagger, so link hover colour lives in the shared rule with a per-property delay list.
- **`team.robotGlyph`** swaps one letter of the robot name for an image (the O in LEMON is a lemon slice). `robotHTML()` implements it and is currently duplicated in **three** places — `binder.js`, `print.js` and inline in `scripts/og-card.html`; change one, change all three and re-run `make-og.sh`. The first two predate `common.js` and would sit more naturally in `window.Binder` now that it exists. It keeps the letter in the DOM under `.vis-hidden`, so the heading still reads and copies as the real name, and falls back to plain text when the glyph is absent or the letter isn't in the name. `.robot-glyph` is sized slightly over the cap height (a circle reads small beside flat-topped letters) and skewed to match the title's italic; the skew does not affect layout but widens the painted box by `height × tan(9°)`, which the side margins pay for — drop them and the neighbouring letters collide with it.
- **Section layout:** the first media block renders beside the feature list; the rest go full width below (`renderSection`).
- **Crossfade stacks** (hero, highlight, iterations) put every frame in one CSS grid cell (`grid-area: 1 / 1`) so the box sizes to the tallest frame — no JS measuring.
- **Hero:** callout `x`/`y` are percentages over the hero image; `layoutHero()` redraws SVG leader lines from DOM positions on load/resize. Callout `id` must match a section `id`. Optional `hl` images crossfade on hover/focus; their `src` is held in `data-src` and only loaded at ≥901px (the rails are hidden below that).
- **Sections** with `print: false` are excluded from print.html.
- **Head metadata is hand-kept, and deliberately duplicated.** Title, description, Open Graph tags and the `schema.org` JSON-LD block live literally in `index.html` and `print.html`, *not* in `content.js`, because search and preview crawlers read the files without running scripts. Same reason for the `<noscript>` block in each `<body>`, which mirrors the section list by hand. Renaming the robot or rolling the season means editing all of these — `GETTING-STARTED.md` has the checklist and the counts. `print.html` is `noindex` with its canonical pointed at `/`, since it is the same words as the web version.
- **Absolute URLs** in the meta tags and JSON-LD are hardcoded to `https://2026.teamkoalafied.com/` (matching `CNAME`) — crawlers can't resolve a relative `og:image`. A domain change touches `CNAME`, both HTML heads, `robots.txt` and `sitemap.xml`.
- **Theming:** design tokens are CSS custom properties in `:root` of `assets/css/binder.css`; `--accent` is overridden at runtime from `team.accent`. Honor the existing `prefers-reduced-motion` handling when adding transitions.

## Image conventions

Images live in `assets/img/` (~1400–1600px wide). All views within one `highlight` or `iterations` set must share identical pixel dimensions — they are same-camera CAD renders crossfaded on top of each other, not overlays.
